# Standalone verified media-volume learning

Clear local commands such as “set media volume to 25%” or “put the volume at 25 percent” now run offline through the verified percentage handler. These explicit built-in commands do not need a learned phrase or cloud interpretation. Their verification result is recorded in the local journal. Other streams, negated/explanatory input and invalid levels are not parsed as explicit local commands.

For new wording, Gemini/the gateway may propose DEVICE_SETTING with entities exactly setting=media_volume and percent=an integer string 0..100. Extra stream IDs, directions or parameters are rejected. The shared volume approval store retains the original phrase and bound percentage; yes executes once, no/unrelated input/expiry cancels. Only verified readback of the nearest supported Android level permits automatic phrase learning when enabled and the lesson is learnable. An already-correct level satisfies this verification. The approval word is never taught.

Saved volume_level entries contain only percent and replay through the same verified handler offline. Failed replay verification pauses only the matching saved meaning; verified successful lessons can restore that same meaning. A different level cannot silently overwrite the old alias. Invalid saved parameters do not run. Review, targeted deletion, dashboard counts and result history include the new capability. Recent timer/app context remains separate. Existing relative-volume approvals and routine definitions retain their behavior.

Tests cover schema and local-command boundaries, approval/original-phrase persistence, offline restoration/review, disabled/failed learning, pauses/reactivation and meaning conflicts. CI compiles and runs Android/gateway tests; source theme/whitespace checks remain separate from phone testing.
