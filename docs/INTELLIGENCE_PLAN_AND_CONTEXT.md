# Intelligence Plan, menus and conversation context

Intelligence opens a category menu rather than a long management form. Select the plan, commands/learning, memory, routines, results, capability requests or AI connection; Back returns to that menu. Appearance similarly separates Themes, Fonts and Chat Contrast. Theme choices use compact rows; existing font validation and previews remain. Tools/Support categories use the same row styling and grouped descriptions.

The Intelligence Plan has seven equally weighted workstreams, engineering scope estimates, implemented/remaining descriptions and separate verification notes. Percentages are not accuracy scores or device proof. The installed app version is shown separately from the plan's evidence version. The bundled plan works offline; Check plan updates explicitly fetches the fixed public GitHub JSON feed without sending chat, credentials, location or other device data. It has timeouts, a 64 KiB limit, strict bounded fields and monotonically newer revisions. Invalid, older and unavailable updates retain the existing plan. There is no downloaded code, approval or capability installation.

`docs/intelligence-plan.json` is the maintained public source and `app/src/main/assets/intelligence-plan.json` is its packaged mirror. Release builds stamp revision/date/evidence-version into both and publish them alongside the normal APK in the updater commit. They do not infer or increase completion percentages from build counts. Future development must update implemented/remaining/verification descriptions and adjust estimates only when justified by the original seven-workstream scope.

Chat context retains at most twelve bounded completed exchanges per conversation in private atomic files, with forty recent context files retained. Serialized UTF-8 files also stay below 64 KiB; large escaped or multibyte exchanges reduce the retained count while keeping the newest complete exchanges. Saved UI conversations can seed older chats. Full saved-command, memory, capability-management and diagnostic review lists, including their supported synonyms and punctuation, are excluded from provider context. Public plan discussions are informational. Providers receive an immutable snapshot captured when their request starts; existing lesson/action admission still applies.

New chat and history selection rotate a durable conversation epoch, including when reopening the same chat, and clear in-memory prompts in each assistant instance when it observes the transition. The UI and `:wake` process share `live-chat-identity.json`; `live-chat-conversation.txt` remains a compatibility mirror and existing chat IDs/text are preserved. Ordinary persistence does not rotate the epoch. Provider proposal admission, fallback lesson admission and context recording validate the original epoch under an interprocess file lock. Nested operations reuse that lock on the same thread. Late background responses cannot record into reopened chats or stage cloud proposals; UI and all foreground-voice callback deliveries also check their captured conversation token. History selection stops active live chat.

Pending routine, volume, app/timer outcome and preference approvals now use private atomic `conversation-pending-*.json` files, tagged with that epoch and a unique revision. Valid same-chat proposals survive process restarts and are shared by UI/voice. Conditional deletion prevents a stale reader from consuming or clearing a newer proposal. Earlier APKs' untagged pending approval preferences are retained but cannot authorize actions after this update; those transient requests require a fresh review. Saved commands, assistant preferences, routines, archives, signing identity and application data are unchanged. Exact-volume readback and explicit learning policies remain separate. Context storage failures can reduce continuity; they never create an approval or learned action. If a context file is evicted, archived chat text can still seed bounded context when reopened.

Plan discussion routes locally while offline: “Show intelligence plan progress”, “What about the capability builder?”, “How far along is that?” and “What's left?”. The selected workstream persists through these follow-ups and saved chat reopening. An unrelated topic or new chat resets that local topic. This is bounded plan discussion plus recent provider context, not unlimited semantic memory or a new on-device generative model.

Validation includes malformed and oversized plans, derived percentages, cache restart/rollback/corruption, per-chat isolation, stale generations and durable epochs, escaped/multibyte size bounds, private-list exclusion, cross-instance approval consumption, stale-reader/new-proposal isolation, nested epoch transactions and local plan follow-ups. Optimized emulator tests include all-theme menu back paths, offline plan rendering at enlarged fonts and conversation transitions, alongside voice/profile regressions. Actual phone navigation, network refresh, conversation switching and speech context need phone checks.
