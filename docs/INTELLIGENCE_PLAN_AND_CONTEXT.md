# Intelligence Plan, menus and conversation context

Intelligence opens a category menu rather than a long management form. Select the plan, commands/learning, memory, routines, results, capability requests or AI connection; Back returns to that menu. Appearance similarly separates Themes, Fonts and Chat Contrast. Theme choices use compact rows; existing font validation and previews remain. Tools/Support categories use the same row styling and grouped descriptions.

The Intelligence Plan has seven equally weighted workstreams, engineering scope estimates, implemented/remaining descriptions and separate verification notes. Percentages are not accuracy scores or device proof. The installed app version is shown separately from the plan's evidence version. The bundled plan works offline; Check plan updates explicitly fetches the fixed public GitHub JSON feed without sending chat, credentials, location or other device data. It has timeouts, a 64 KiB limit, strict bounded fields and monotonically newer revisions. Invalid, older and unavailable updates retain the existing plan. There is no downloaded code, approval or capability installation.

`docs/intelligence-plan.json` is the maintained public source and `app/src/main/assets/intelligence-plan.json` is its packaged mirror. Release builds stamp revision/date/evidence-version into both and publish them alongside the normal APK in the updater commit. They do not infer or increase completion percentages from build counts. Future development must update implemented/remaining/verification descriptions and adjust estimates only when justified by the original seven-workstream scope.

Chat context retains the last twelve bounded completed exchanges per conversation in private atomic files, with forty recent context files retained. Saved UI conversations can seed older chats. Full saved-command, memory, capability-management and diagnostic review lists are excluded from provider context. Public plan discussions are informational. Providers receive recent context as context only; existing lesson/action admission still applies.

New chat and history selection bind a new context generation and clear old pending approvals in the UI assistant. Late background responses cannot record into another chat or stage its cloud proposals; UI and foreground-voice callback delivery also check their captured conversation token. Ordinary app/timer/volume approvals, exact-volume readback and explicit learning policies remain separate. Context storage failures can reduce continuity; they never create an approval or learned action. If a context file is evicted, archived chat text can still seed bounded context when reopened.

Plan discussion routes locally while offline: “Show intelligence plan progress”, “What about the capability builder?”, “How far along is that?” and “What's left?”. The selected workstream persists through these follow-ups and saved chat reopening. An unrelated topic or new chat resets that local topic. This is bounded plan discussion plus recent provider context, not unlimited semantic memory or a new on-device generative model.

Validation includes malformed and oversized plans, derived percentages, cache restart/rollback/corruption, per-chat isolation, stale generations, bounds, private-list exclusion and local plan follow-ups. Six optimized emulator tests include all-theme menu back paths and offline plan rendering at enlarged fonts, alongside voice/profile regressions. Actual phone navigation, network refresh, conversation switching and speech context need phone checks.
