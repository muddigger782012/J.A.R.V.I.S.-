# App proposal corrections before approval

`use Firefox instead` or `actually, open Chrome instead` revises an unrequested app proposal only when Android resolves one launchable installed app with an exact launcher label. The replacement package/label is host-resolved; text cannot supply an arbitrary package or launch intent. A fresh yes/no approval is required, and success feedback is still required before learning. Original proposal expiry remains unchanged.

Explicit teaching keeps the chosen alias for the revised target. Ordinary AI proposal edits disable original-phrase learning so `open Chrome` cannot be learned as opening Firefox. Confirmed success may still update recent-action memory. Missing/ambiguous/unlaunchable apps and storage failures retain the original target. Running/requested actions, timer proposals and contextual preferred/repeat references remain locked. Correction phrases are reserved against learning.

Phone check offline with two installed apps: teach a new alias (for example `desk app`) to open Chrome; say `use YouTube instead` using the exact name of another installed app; ask `what am I approving`; approve; verify that only the revised app opened; say `it worked`; inspect saved commands and replay the alias offline. If no second app has that launcher name, the proposal must remain Chrome and ask for an exact installed name.
