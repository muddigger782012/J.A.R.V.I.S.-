# Approved trial of an existing capability

`try capability request` followed by an exact saved description freshly assesses the request locally, then stages a timer, uniquely resolved installed app or exact media-volume proposal in the existing expiring approval store. It does not run anything until yes. Unknown, missing-app, invalid-duration, relative-volume and updater requests receive guidance without a proposal. Lookup is exact and read-only; the backlog is neither removed nor marked implemented or verified.

The pending phrase is the canonical action command, not the capability-management control or private backlog description. Trials create no learned alias, even after success. App/timer results enter recent-action memory only after the user checks them and reports success; exact volume uses device readback. Existing cancellation, expiry, one-shot approval, storage-failure and parameter-edit rules apply. A later trial reassesses app availability; an earlier review cannot authorize execution. Private initial trial replies do not enter AI history. No code generation or new feature installation is provided.
